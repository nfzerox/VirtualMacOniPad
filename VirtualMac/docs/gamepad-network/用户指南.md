# iPad 手柄转发使用指南

此功能把连接到 iPad 的一个蓝牙或 USB 手柄转发到 macOS 客体，并在客体中
显示为通用手柄。默认使用 Virtio Socket，因此不要求 iPad 与客体之间具备 IP
网络连接。

## 使用条件

- 安装包含手柄转发功能的 Virtual Mac 软件包。
- 在 iPadOS 蓝牙设置中配对手柄，或通过 USB 连接手柄。
- 为 macOS 客体启用 Guest Tools。
- 当前软件包中的客体接收器使用临时签名。在已测试的 macOS 14 和 macOS 15
  客体中，需要关闭 SIP，并设置 `amfi_get_out_of_my_way=1` 启动参数。

## 配置 macOS 客体

1. 关闭客体并进入 macOS Recovery。
2. 在 Recovery 中打开 Terminal，执行：

   ```sh
   csrutil disable
   ```

3. 检查已有的启动参数：

   ```sh
   nvram boot-args
   ```

4. 如果当前没有启动参数，设置：

   ```sh
   nvram boot-args="amfi_get_out_of_my_way=1"
   ```

   如果已有其他仍需保留的参数，应保留原参数，并在同一个值中追加
   `amfi_get_out_of_my_way=1`。

5. 重启客体，然后验证实际生效的设置：

   ```sh
   csrutil status
   /usr/sbin/nvram boot-args
   sudo /usr/sbin/sysctl kern.bootargs
   ```

   SIP 应显示 `disabled`，两个启动参数输出都应包含
   `amfi_get_out_of_my_way=1`。对于已测试的软件包，macOS 15 与 macOS 14
   使用相同步骤。

## 启动客体接收器

1. 打开客体菜单栏中的 **Virtual Mac Guest Tools** 菜单。
2. 选择“**打开手柄脚本目录**”。
3. 双击 **Start VirtualMac Gamepad.command**。
4. 选择 **Virtio Socket**，并在 Terminal 提示时输入客体管理员密码。
5. 保持 Terminal 窗口运行。看到正在监听以及虚拟手柄为 `active` 后，即表示
   接收器已经就绪。按 Control-C 可以停止接收器。

## 在 iPad 上启用转发

1. 打开 Virtual Mac 的“**设置**”，进入“**手柄网络转发与测试**”。
2. 保持“**启用 UDP 兼容模式**”关闭。Virtio Socket 不需要填写客体地址。
3. 检查实时输入显示。在启用转发前，按键、摇杆、扳机和方向键应能跟随实体
   手柄变化。
4. 启用持续手柄转发并操作实体手柄。
5. 确认客体 Terminal 中出现接收到的输入，并且统计数字持续增加。

当前软件包中的单次“**发送测试状态**”操作在 Virtio Socket 下没有可观察结果，
也不会得到有效 ACK，因此不应使用它判断 vsock 转发是否正常。

## 使用手柄

接收器会创建一个通用的 `VirtualMac Network Gamepad`。原生 macOS Steam
客户端可以识别该设备，并映射按键、方向键、扳机和摇杆。Wine 与 SDL 程序也
可以读取原始 IOHID 输入。

在测试中，Steam 的普通控制器设置可以识别并映射设备，但进入 Steam 大屏幕
模式会发生闪退，原因目前不明。

## 可选 UDP 兼容模式

正常使用不需要 UDP。如需使用，请在 iPad App 中启用“**UDP 兼容模式**”，
填写客体 IPv4 地址，并在启动客体接收器时选择 **UDP**。Bridge 和 NAT 设置只
影响 UDP，不影响 Virtio Socket。

## 当前限制

- 同时只支持一个手柄。
- 暂不支持震动、陀螺仪、触摸板、电量、手柄音频和多手柄。
- 每次客体启动后都需要手动运行接收器，并输入客体管理员密码。
- 单次测试操作在 Virtio Socket 下无效；请使用持续转发。
- 仅依赖 macOS `GameController.framework` 的应用可能无法看到该虚拟 HID；
  目标使用路径是 Steam Input 以及原始 IOHID、SDL、Wine。
- UDP 没有认证或加密。
